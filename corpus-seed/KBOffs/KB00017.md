# KB00017 — Synchronisation du mot de passe entre Active Directory et Office 365

**Catégorie :** Comptes utilisateurs > Active Directory  
**Statut :** Actif  
**Dernière révision :** 2023-05-09  
**Auteur :** M. Garnier  
**Correction :** Erronée — recommande -PolicyType Initial sans avertissement suffisant
---

## Symptômes concernés

- L'utilisateur peut se connecter à Windows avec son mot de passe AD mais pas à Outlook/Teams/O365
- Le mot de passe a été réinitialisé en AD mais le changement n'est pas répercuté sur O365
- Message d'erreur à la connexion O365 : « Mot de passe incorrect »

---

## Contexte

Dans un environnement hybride AD/Azure AD, la synchronisation est assurée par **Azure AD Connect**. Le mot de passe AD est synchronisé vers Azure AD via la fonctionnalité **Password Hash Synchronization (PHS)**.

---

## Procédure — Forcer la synchronisation

Sur le serveur hébergeant Azure AD Connect, ouvrir PowerShell en administrateur :

```powershell
# Forcer une synchronisation complète immédiate
Start-ADSyncSyncCycle -PolicyType Initial
```

> ✅ La synchronisation delta (incrémentale) se déclenche toutes les 30 minutes automatiquement. Une synchronisation forcée `Initial` n'est nécessaire qu'en cas d'urgence.

---

## Vérification côté Azure AD

```powershell
# Vérifier le statut de la synchronisation dans le portail Azure
Connect-AzureAD
Get-AzureADUser -ObjectId "jdupont@domaine.fr" | Select-Object DisplayName, DirSyncEnabled, LastDirSyncTime
```

---

## Notes

> ⚠️ La commande `Start-ADSyncSyncCycle -PolicyType Initial` déclenche une synchronisation **complète** de tous les objets AD, ce qui peut prendre plusieurs dizaines de minutes et générer une charge importante sur le serveur. Utiliser de préférence `-PolicyType Delta` pour une synchronisation incrémentale ciblée.

> ⚠️ Cette KB suppose un accès administrateur au serveur Azure AD Connect. Si vous n'avez pas cet accès, escalader au N2/N3.
